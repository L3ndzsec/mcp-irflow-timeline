IRFlow MCP Workflow

IRFlow MCP — DFIR Analysis Workflow

How to invoke the MCP server tools in Claude (terminal or desktop) for a forensic investigation

Before you start

IRFlow Timeline must be open and have at least one tab loaded. The MCP server reads the live manifest written to %APPDATA%\IRFlow Timeline\mcp-manifest.json. No tabs open = no data. Claude Code users: the server is already registered — just start talking.

PHASE 1

Orient — what do I have?

Run this at the start of every investigation. Get the lay of the land before going deeper.

1
list_sessions See all loaded tabs

Returns every open tab: tabId, file name, row count, columns, and detected timestamp columns.

Say to Claude
what tabs do I have loaded in IRFlow?
2
get_event_stats Get a DFIR summary of each tab

Date range, top event IDs, top hosts, users, source IPs, logon types, processes — one call gives the full picture.

Say to Claude
give me a DFIR summary of the Security.evtx tab — top event IDs, hosts, and users
3
get_columns Learn the schema before querying

Returns column names and 5 sample values each. Essential when column names are vendor-specific or abbreviated.

Say to Claude
what columns are in the Sysmon tab and what do they look like?
PHASE 2

Threat-area analysis

Use the built-in DFIR analyzers. These tools understand the forensic context — no SQL needed.

4
get_lateral_movement_summary Logon pairs, failed logons, RDP patterns

Analyses Security / TerminalServices data: source→target pairs, logon type breakdown, failed logon accounts, top source IPs. Designed for 4624 / 4625 / 4648 events.

Say to Claude
analyse lateral movement in the WIN-LLC Security tab. Who moved where and when?
which accounts had the most failed logons? are any of them suspicious?
5
get_process_execution_summary Parent→child chains, suspicious cmdlines

Analyses Sysmon / 4688 data: top processes, parent→child chains, LOLBAS/LOLBin patterns, encoded PowerShell, and top executing accounts.

Say to Claude
summarise process execution in the Sysmon tab. flag any suspicious parent-child relationships or encoded commands
what processes did Administrator run? anything that looks like living-off-the-land?
→ After either summary, ask Claude to interpret the findings in a DFIR context: "what does this tell me about the attacker's technique?" or "map these findings to MITRE ATT&CK". The LLM adds the analytical layer on top of the raw data.
PHASE 3

Targeted queries

Drill into specific IOCs, time windows, or user accounts with filtered queries and full-text search.

6
query_events Filtered rows — user, host, event ID, date range

Supports column filters (exact or LIKE), ISO 8601 date range, column selection, and row limit (max 1000).

Say to Claude
show me all logon events for Administrator on DESKTOP-0QT8017 between 2018-07-28 00:00 and 2018-07-28 02:00
get me all event ID 4625 rows where the source IP contains 118.93
7
search_events Full-text search across all columns

Uses the FTS5 index when available (fast, ranked). Falls back to LIKE search. Supports FTS5 syntax: AND, OR, NOT, phrase quotes, prefix *.

Say to Claude
search the Sysmon tab for -encodedcommand
search for "net user" OR "whoami" OR "mimikatz" across all process execution events
PHASE 4

Free-form SQL

For anything the built-in tools don't cover — custom aggregations, joins, window functions, timeline pivots.

8
run_sql Direct read-only SELECT against the SQLite database

Main table is data. Only SELECT and WITH … SELECT are allowed. Row cap: 2000. Ask Claude to write the SQL for you — it knows the schema from get_columns.

Say to Claude
write SQL to count events per hour for the Security tab and show me the busiest hours
find all users who logged on from more than 3 different source IPs in the same day
using run_sql, get me the 10 minutes with the highest event volume in the Sysmon tab
! Always run get_columns before asking Claude to write SQL for an unfamiliar tab. Column names in the database are sanitized (spaces and special chars replaced) — Claude needs the actual names to generate correct queries.
Quick reference — tool × investigation type
Tool Use when… Phase
list_sessions Starting any session — confirms what data is loaded START
get_event_stats First DFIR read of a tab — date range, top actors, event volume START
get_columns Before any query — unknown schema or vendor-specific field names START
get_lateral_movement_summary Security / TerminalServices log — logons, pivots, RDP, failed auth DEEP
get_process_execution_summary Sysmon / 4688 log — execution chains, LOLBAS, encoded commands DEEP
query_events Known IOC — filter by user, host, event ID, or time window DEEP
search_events Hunting a keyword, hash, IP, or tool name across all columns DEEP
run_sql Custom aggregations, time-bucket pivots, cross-column correlation FREE
